## Overview

CodeEngine is a full-stack SaaS developer tool built to help engineers understand unfamiliar codebases quickly. Point it at any public GitHub repository and within minutes it produces:

- A plain-English **architecture summary** generated by an LLM
- An interactive **dependency graph** (files → classes → functions)
- A prioritized list of **bugs and code issues** found by both static analysis and LLM reasoning
- Actionable **refactoring suggestions** with side-by-side code diffs
- A **RAG-powered Q&A chat** — ask anything about the code in plain English

The platform is designed to the same quality bar as Linear or Vercel: dark-first, animation-rich, and dense without feeling cluttered.

### Clean Architecture (Python backend)

```
api/              FastAPI routes + WebSocket
core/             Config, logging, exceptions
domain/           Models + interfaces (ports)
services/         Business logic (AuthService, RAGService, …)
infrastructure/   DB adapters, ChromaDB, NetworkX/Neo4j, Redis
parsers/          AST parsers — Factory + Visitor patterns
workers/          Celery background tasks
tests/            18 unit + integration tests
```

### Design Patterns Used

| Pattern | Where |
|---|---|
| **Factory** | `parsers/factory.py` — selects parser by file extension |
| **Visitor** | `parsers/python_parser.py` — walks Python AST |
| **Strategy** | `domain/interfaces.py` — `ICodeParser`, `ILLMClient` |
| **Repository** | `infrastructure/database/repositories/` — DB abstraction |
| **Dependency Injection** | FastAPI `Depends()` for auth, sessions |
| **Clean Architecture** | Domain → Services → Infrastructure, no inward deps |

## Features

### Analysis Pipeline

```
POST /engine/analyze-repo
  │
  ├─ RepoIngestionService   clone via GitPython
  ├─ ParserService          Python AST / JS regex → FileAnalysis
  ├─ EmbeddingService       chunk code → ChromaDB vectors
  ├─ BugDetectionService    static rules + LLM semantic scan
  ├─ RefactorService        code-smell detection + LLM suggestions
  └─ SummaryService         LLM architecture narrative
        │
        └─ status = "complete"   WebSocket notifies frontend
```

### Frontend Pages

| Route | Description |
|---|---|
| `/` | Marketing landing — hero, features, how it works |
| `/login` | Split-screen auth with testimonial panel |
| `/register` | Split-screen auth with platform stats |
| `/dashboard` | Repo grid + inline submit form |
| `/repo/:id` | 5-tab analysis view |

### API Reference

**Auth**
```
POST /engine/auth/register   → { access_token, user_id, email, username }
POST /engine/auth/login      → { access_token, user_id, email, username }
GET  /engine/auth/me         → user profile  [Bearer]
```

**Repositories**
```
POST   /engine/analyze-repo           submit GitHub URL
GET    /engine/repo-summary           list all repos
GET    /engine/repo-summary/{id}      status + architecture summary
GET    /engine/my-repos               user's repos  [Bearer]
DELETE /engine/repo/{id}              delete repo   [Bearer, owner]
```

**Analysis**
```
GET  /engine/dependency-graph/{id}    node-link graph
GET  /engine/issues/{id}              bugs (filter: severity, file)
GET  /engine/refactor/{id}            suggestions (filter: effort)
POST /engine/ask                      RAG Q&A + source citations
```

**Real-time**
```
WS   /engine/ws/progress/{id}         analysis progress stream
```

## Getting Started

### Option A — Docker Compose (recommended)

```bash
git clone <this-repo>
cd <this-repo>/artifacts/codebase-engine

cp .env.example .env
# Edit .env — set OPENAI_API_KEY and JWT_SECRET

docker compose up -d
```

| Service | URL |
|---|---|
| Frontend | http://localhost |
| API docs (Swagger) | http://localhost/engine/docs |
| Celery monitor | `docker compose --profile monitoring up -d` → http://localhost:5555 |

### Option B — Local Development

**Requirements:** Python 3.11+, Node.js 20+, pnpm

```bash
# 1. Clone
git clone <this-repo> && cd <this-repo>

# 2. Install JS dependencies
pnpm install

# 3. Python backend
cd artifacts/codebase-engine
pip install -r requirements.txt
cp .env.example .env   # add OPENAI_API_KEY + JWT_SECRET
PYTHONPATH=. python main.py   # starts on :8000

# 4. Frontend (new terminal, from repo root)
pnpm --filter @workspace/codebase-ui run dev   # starts on :19556
```

## Environment Variables

Copy `artifacts/codebase-engine/.env.example` to `.env` and fill in:

| Variable | Required | Description |
|---|---|---|
| `OPENAI_API_KEY` | Yes | Your OpenAI API key |
| `JWT_SECRET` | Yes | Random string for signing JWTs — change in production |
| `DATABASE_URL` | No | PostgreSQL URL (defaults to SQLite) |
| `REDIS_URL` | No | Redis URL (defaults to in-memory fallback) |
| `LLM_MODEL` | No | Default `gpt-4o-mini` |
| `NEO4J_URI` | No | Activates Neo4j graph store |
